# Embedded and Cooperating Components

## 1. Identify the Actual Components

Trace “actual installation/build artifact → consumer release version or revision → applicable official requirements.” Read release documentation directly when it covers the installed version. Resolve a source SHA only for source-specific requirements or unclear version mappings.

- **Embedded components**: start from the torch commit's [c10/xpu/CMakeLists.txt](https://github.com/pytorch/pytorch/blob/v2.15.0/c10/xpu/CMakeLists.txt), [caffe2/CMakeLists.txt](https://github.com/pytorch/pytorch/blob/v2.15.0/caffe2/CMakeLists.txt), and `third_party` pins. Follow `include`, `find_package`, `target_link_libraries`, and download declarations. Confirm versions through component version output, release build records, or local `CMakeCache.txt`/logs. A pin confirmed as used by this build is version evidence; static artifacts need not independently report a SHA. If only the parent repository's pin is known, label it the expected version and check overrides and actual enablement. Use `RECORD` for shared-library ownership and build targets/link declarations for headers or static libraries.
- **Independently installed components**: check parent-package constraints using [wheel.md](wheel.md), then select documentation for the compliant installed release. Resolve commit suffixes to unique SHAs in the official repository and cross-check bundled version declarations or relevant source files. Matching files support only checks involving those files, not the entire binary's identity. PyTorch CI pins must correspond to the installed artifact. Do not expand dependency edges whose packages are missing, out of range, or have unconfirmed constraints.
- **Enablement**: use actual build options and functionality provided by the installation. A component's presence in source does not mean this build enabled it.

## 3. SYCL-TLA Model-Specific Requirements

At the actual TLA revision, cross-read README minimum requirements, the build guide, and validated configurations, retaining each statement's scope. For example, the [v0.9 README](https://github.com/intel/sycl-tla/blob/b4f7216580a48b1d443d0c6e85dc7a72105bbdbb/README.md#compatibility) explicitly requires **IGC >= 2.27.10** for PVC. The Runtime 25.13 / IGC 2.10.10 combination in the [same-version build guide](https://github.com/intel/sycl-tla/blob/b4f7216580a48b1d443d0c6e85dc7a72105bbdbb/media/docs/cpp/build/building_with_sycl_support.md) does not override that model-specific minimum. Preserve the difference in the report. For B580 and other build conditions, record the combination as stated in the guide's Requirements section; do not rewrite a parenthesized IGC version as an independent lower bound.

Apply that threshold only to the matching revision and model. If another GPU, such as B70 in this version, appears only in a validation table or [CMake device targets](https://github.com/intel/sycl-tla/blob/b4f7216580a48b1d443d0c6e85dc7a72105bbdbb/CMakeLists.txt), do not infer its IGC minimum. After checking the corresponding sources, classify the absence of an explicit requirement as No explicit requirement found.

## 4. Build Environment (When Requested)

Read actual tool paths, versions, and host/device flags from build caches/logs, then compare with matching source:

| Build target | Sources to inspect |
|---|---|
| PyTorch XPU / extensions | `cmake_minimum_required`, `CMAKE_CXX_STANDARD`, and compiler comparisons in [PyTorch CMakeLists.txt](https://github.com/pytorch/pytorch/blob/v2.15.0/CMakeLists.txt); SYCL conditions and device flags in [xpu.cmake](https://github.com/pytorch/pytorch/blob/v2.15.0/cmake/public/xpu.cmake) and [FindSYCLToolkit.cmake](https://github.com/pytorch/pytorch/blob/v2.15.0/cmake/Modules/FindSYCLToolkit.cmake); `build-system` in [pyproject.toml](https://github.com/pytorch/pytorch/blob/v2.15.0/pyproject.toml). Distinguish a preference for Ninja from a hard requirement; also check TLA's CMake when enabled. |
| oneDPL / oneTBB | Select the bundle from the DLE/OMIX row matching PyTorch. Use the [DLE installation guide](https://www.intel.com/content/www/us/en/docs/oneapi-toolkit/installation-guide-linux/latest/install-intel-deep-learning-essentials.html) to locate `intel-deep-learning-essentials-*` dependencies or offline package manifests. Then read System Requirements in the corresponding [oneDPL Guide](https://www.intel.com/content/www/us/en/docs/onedpl/developer-guide/2022-12-0/intel-oneapi-dpc-library-introduction.html), and Minimum Requirements / Supported Compilers in [oneTBB Requirements](https://www.intel.com/content/www/us/en/developer/articles/system-requirements/intel-oneapi-threading-building-blocks-system-requirements.html). Apply conditions according to host/device usage. |
| Unified Runtime | Use [intel/llvm UR](https://github.com/intel/llvm/tree/sycl/unified-runtime) matching DPC++ (for standalone releases, use the [UR repository](https://github.com/oneapi-src/unified-runtime)). | IGC | At the corresponding tag, read [documentation/build_ubuntu.md](https://github.com/intel/intel-graphics-compiler/blob/v2.40.16/documentation/build_ubuntu.md), the Revision table, and `IGC_OPTION__LLVM_PREFERRED_VERSION`.
