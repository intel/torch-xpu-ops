# Domain: XPU Kernel / Operator

Reference material loaded by `fix-root-cause` when it emits
`domain: xpu-kernel`. Not a standalone skill. See `SKILL.md` and
`domain-registry.md` in the same directory for the routing contract.

## Path conventions

- torch-xpu-ops: `src/ATen/native/xpu/sycl/`, `src/ATen/native/xpu/`.
  Inside a PyTorch checkout: `third_party/torch-xpu-ops/<path>`.
- pytorch: `torch/`, `aten/src/ATen/`, `test/`, `c10/`, `torch/_dynamo/`,
  `torch/_inductor/`. Never `third_party/torch-xpu-ops/`.

## CUDA cross-reference

CUDA counterparts live in `agent_space_xpu/pytorch/`:

- `src/ATen/native/xpu/<Op>.cpp` → `aten/src/ATen/native/<Op>.cpp`
- `src/ATen/native/xpu/sycl/<Op>Kernels.cpp` → `aten/src/ATen/native/cuda/<Op>.cu`

For ported tests, find the original under
`agent_space_xpu/pytorch/test/` and compare tolerances, dtypes, and
device assumptions.

## Missing kernel

If the XPU kernel for an op doesn't exist yet
(`NotImplementedError`, "could not run ... with backend XPU", or a
UT skip citing a missing XPU kernel), the fix strategy is to
**implement it aligned with the CUDA kernel**
(`aten/src/ATen/native/cuda/<Op>.cu` / its structured/composite
counterpart), not to skip or xfail the UT. See "CUDA
cross-reference" above for the file mapping.

## Test path resolution

Working directory is `$PYTORCH_DIR/`.

| Input | Resolution |
|---|---|
| `test/xpu/*.py` | `third_party/torch-xpu-ops/test/xpu/*.py` |
| `third_party/torch-xpu-ops/...` | use as-is |
| CI dotted name | `third_party.torch-xpu-ops.test.xpu.test_ops_xpu` → `third_party/torch-xpu-ops/test/xpu/test_ops_xpu.py` |
| Upstream pytorch path | use as-is |

XPU test classes are often generated by
`instantiate_device_type_tests` (`<BaseClass>XPU`). Verify the
class name before running.

## CPU fallback ops

Not all ATen ops have native XPU kernels. Ops without one fall back
to CPU automatically: inputs are copied to CPU, the CPU kernel runs,
and results are copied back to XPU. The authoritative list lives in
`fallback_list` inside `src/ATen/native/xpu/XPUFallback.cpp`.

When debugging a performance issue or an unexpected CPU-side
execution, check `fallback_list` first to see whether the op is
falling back. Set `PYTORCH_DEBUG_XPU_FALLBACK=1` to log detailed
fallback information at runtime.

Only remove an entry from `fallback_list` after the native XPU
kernel is implemented **and** its dispatch is registered in
`aten/src/ATen/native/native_functions.yaml` in PyTorch.
